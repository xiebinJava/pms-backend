# DSH Agent 选择与 PMS 专属 Agent 方案

## 目标

在 DSH 对话输入框下方提供 Agent 选择器。用户可以选择“自动选择”、通用 Agent 或 PMS 项目助手；当选择 PMS 项目助手时，DSH 使用 PMS 专属提示词、Skill 和插件，并以当前用户权限调用 PMS。

## 核心决策

1. Agent 的运行时和最终配置源在 DSH，PMS 只提供 PMS 业务页面、业务 API 和最终权限校验。
2. 优先扩展 DSH 已有的 `agent-preset` 能力，不另建一套平行的 Agent 注册体系。
3. 第一版的 Agent 选择只对“尚未发送第一条消息的会话”开放；会话开始后锁定 Agent，输入框附近改为只读标签。
4. 后续如需中途切换，创建新的会话分支；不把完整历史直接交给另一个 Agent。
5. Agent、Prompt、Skill 和插件都按已发布版本绑定到会话，发布新版本不改变进行中的会话。
6. 前端选择的 Agent 只是请求意图，DSH 后端必须重新校验 Agent、Skill、插件、工作区和当前用户权限。
7. PMS 的写操作继续执行“预览 → 用户明确确认 → 执行”，Agent 选择不能绕过该流程。

## 用户交互

输入框底部工具栏展示：

```text
[新增] [Agent：自动选择 ▾] [工作区上下文]              [模型 ▾] [发送]
```

Agent 菜单显示名称、简介、当前状态和启用能力。候选项包含：

- 自动选择
- 通用助手
- PMS 项目助手

优先级固定为：

```text
用户手动选择 > 当前工作区默认 Agent > 自动路由 > 通用 Agent
```

打开 PMS 工作区时默认推荐 PMS 项目助手，但不能覆盖用户已经手动选择的 Agent。

会话首次发送消息后，Agent 选择锁定。切换控件变为只读，显示当前 Agent 和版本；用户需要切换时通过“新建会话并使用此 Agent”创建新的会话分支。

## PMS Agent 能力

PMS Agent 至少包含：

- 身份提示词：说明自己是 PMS 项目管理助手；
- 工作提示词：规定只能使用 PMS 工具查询事实，不得猜测；
- PMS 查询 Skill：项目、节点、任务、成员、排期和统计；
- PMS 操作 Skill：项目创建、任务创建、节点负责人、排期、成员、归档和删除；
- PMS 插件：PMS 查询工具、命令预览工具、命令执行工具；
- 输出规则：用户可见字段使用中文，标识符保留原始值；
- 安全规则：最终权限由 PMS 校验，写操作必须二次确认。

PMS 页面上下文只传递页面类型、项目编号、节点编号等定位信息；业务数据通过 PMS 工具实时查询，避免把整页快照塞入每次对话。

## 运行时权限

最终可用能力为：

```text
Agent 允许的工具
∩ 当前用户权限
∩ 当前工作区能力
∩ PMS 当前委派权限
```

DSH 不使用固定管理员身份替代当前用户。PMS 仍然根据当前用户完成项目级、组织级和操作级鉴权。

## 配置页面

DSH 的 Agent 设置页面提供：

- Agent 基本信息；
- “我是谁”提示词；
- “我怎么工作”提示词；
- 已绑定 Skill；
- 已绑定插件和工具；
- 适用工作区；
- 草稿保存、发布、版本历史和回滚；
- 只读测试对话。

配置页面只绑定已经注册的 Skill 和插件，不执行用户输入的任意代码。测试对话默认禁止真实写入，只允许查询和生成预览。

## 非目标

第一版不包含：

- 任意第三方插件在线安装；
- Agent 自动修改自身提示词；
- 多个 Agent 并行执行同一个 PMS 写操作；
- 在已有会话中直接替换整套工具和系统提示词；
- 用 Agent 配置替代 PMS 的业务权限系统。

## 验收标准

1. 新会话输入框下方可以选择 PMS 项目助手。
2. PMS Agent 会话显示正确的 Agent 名称和版本。
3. PMS Agent 只能看到允许的 PMS 工具。
4. 普通 Agent 无法直接调用 PMS 写工具。
5. 首条消息发送后 Agent 不能静默切换。
6. 发布新版本后旧会话行为不变，新会话使用新版本。
7. PMS 查询仍以 PMS 实时返回为准。
8. PMS 写操作仍必须预览并等待明确确认。
9. Agent 配置测试不会真实修改 PMS 数据。
10. 刷新页面或重新连接后，会话仍能恢复原 Agent 和版本。
