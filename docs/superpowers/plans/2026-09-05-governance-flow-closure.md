# 当前治理链路闭环实施计划

## 目标

补齐需求范围、方案设计与计划资源风险三个节点的关键成功流程测试，并把基线保存、确认、重新打开、方案提交、评审人与决策等关键动作写入现有操作日志，确保权限和已删除字段的约束可回归验证。

## 实施步骤

1. 扩展后端审计动作枚举，统一使用 `PROJECT_NODE` 作为资源类型，记录项目、节点、操作前后状态。
2. 为三个节点服务增加成功动作日志：草稿保存、提交/评审/决策确认、基线确认和重新打开。
3. 先补服务层测试：成功流程必须写入正确 action、resourceId 和 projectId；失败流程不写成功日志。
4. 补充数据库迁移与权限回归检查，确认需求目标/交付字段及方案包旧字段没有重新暴露。
5. 运行后端全量测试、前端全量测试、类型检查和构建；前端页面做一次桌面端与移动端烟测。

## 验收标准

- 需求基线确认/重新打开、方案包提交/评审/决策确认、计划基线保存/确认/重新打开均有可查询的成功审计动作。
- 权限、节点完成前置条件和乐观锁失败行为保持不变。
- 所有新增测试先验证失败，再通过；后端和前端现有测试全部通过。
- 不恢复已经删除的字段，不改变“需求确认仍需人工确认”的规则。
