# 业务验收与缺陷闭环实施计划

## 目标

把已确认的业务验收 Demo 落到正式前后端：验收项从已确认需求只读生成，验收结果与遗留事项由验收节点维护；缺陷只在本节点展示关联摘要，缺陷状态和关闭动作预留给未来的缺陷管理模块负责。

## 实施步骤

1. 新增验收节点迁移、实体、DTO、Mapper、服务和接口，支持读取、保存草稿、确认和重新打开；验收项必须覆盖已确认需求，确认时校验验收结果与条件通过遗留事项。
2. 增加轻量缺陷关联摘要表和关联接口，只允许记录/展示缺陷编号、标题、级别、处理状态、影响说明，不提供验收页关闭或修改缺陷状态的能力。
3. 将验收确认纳入节点完成后端门禁和操作日志，确保 UI 状态不能绕过后端规则；不恢复已删除的目标、交付或方案包旧字段。
4. 在项目详情页增加验收工作台，提供验收项结果、关联缺陷摘要、验收结论和残留事项；沿用现有节点权限、只读和完成节点交互模式。
5. 先补后端服务/完成门禁测试，再补前端完成条件/API/组件源代码测试；最后运行后端全量测试、前端全量测试、类型检查、构建和 Playwright 烟测。

## 验收标准

- 已确认需求全部出现在验收项中，且验收页不能编辑需求名称和验收标准。
- 所有验收项通过，或条件通过且填写遗留事项时，才允许确认验收结论；失败/待验收不能确认。
- 缺陷只显示关联摘要，并可跳转/预留创建入口；验收页不出现关闭、修改缺陷状态等操作。
- 验收确认后节点完成仍受服务端门禁保护，重新打开后可以修改验收内容。
- 不保留已经删除的目标/交付字段，需求确认仍然是人工确认。
- 新增测试先失败后通过，现有测试不回归失败。
