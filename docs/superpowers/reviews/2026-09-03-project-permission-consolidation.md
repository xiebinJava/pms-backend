# 项目权限与数据范围收口 Review（2026-09-03）

## 结论

本次项目域权限收口已完成实现、回归测试和静态 review。项目读取、创建、常规写入、项目治理、评论、生命周期、资源绑定和前端 capability 已按同一套规则落地；人员、组织、审计和反馈仍保持独立权限边界。

## Review 范围

- `project:read` 固定全公司读取，覆盖未删除项目的任务、节点、里程碑、评论、附件、成员和关注人。
- 所有标准角色具备 `project:create`；创建时不填写项目经理，首节点确认时单独选择。
- 创建人和项目经理拥有相同项目级责任权限；治理角色按功能权限与组织范围操作；任务/节点负责人保留有限责任写入。
- 已终止项目只读且仅恢复例外；已删除项目对普通读取按不存在处理。
- 搜索、图片、成员、关注人、任务附件和评论的项目 ID 绑定，以及前端项目/节点/任务 capability。

## Review 发现与处理

| 发现 | 处理 |
| --- | --- |
| 节点负责人调整误用常规写入口，可能让普通 `project:write` 角色参与负责人治理 | 改为 `project:manage`，与 `canAssignNodeOwner` 和权限矩阵一致 |
| 前端普通项目写入者保存资料时可能顺带提交成员、关注人或项目经理字段 | 按 `canManageMembers` / `canSetProjectManager` 组装 payload，避免越权字段触发或绕过服务校验 |
| 任务看板曾有 permissive capability fallback | 改为只信任后端 `node.permissions.canManageTasks`，默认拒绝 |
| 项目图片旧 URL 未携带项目 ID，OpenAPI 与限流路径也未同步 | 增加项目图片持久化绑定、项目级 URL、删除接口、OpenAPI 路由和限流匹配 |
| 已完成项目无法进入节点回滚入口 | 增加回滚专用项目状态检查，允许 ACTIVE/COMPLETED，仍拒绝 TERMINATED/DELETED，并保留项目治理校验 |
| 已删除项目普通直链返回 422，不符合按不存在处理的 HTTP 语义 | 增加统一 404 业务码、异常映射和回归测试；恢复入口仍可加载已删除项目 |
| 本地验收默认上传目录 `/var/lib/pms/uploads` 在开发机不可写 | 验收进程使用开发专用 `/private/tmp/pms-uploads`；生产仍通过 `PMS_UPLOAD_DIR` 配置可持久化目录 |
| 历史手册和旧组织设计稿存在“普通员工不能创建”或“只有创建人/经理能终止”的旧文案 | 更新当前手册与中英文 locale；历史设计稿增加以 2026-09-03 项目权限规范为准的说明 |
