# 子任务管理增强设计

## 目标

让子任务具备完整但不过度复杂的日常管理能力：可选截止日期、状态选择、单项删除，并在主任务完成时由后端保证子任务同步完成和日期补齐。

## 已确认的业务规则

1. 子任务截止日期是可选字段。没有填写截止日期的子任务不参与单独的临期/逾期提醒。
2. 子任务可以选择“待办、进行中、已完成”，编辑权限沿用任务接口返回的 `TaskPermissionsDTO.canEdit`；没有权限时前端只读，后端仍是最终校验者。
3. 删除子任务使用现有任务删除接口和 `canDelete` 能力，并弹出确认提示。子任务不能再拆分子任务，因此不需要额外的递归删除交互。
4. 当父任务被更新为“已完成”时，后端在同一事务中：
   - 将该父任务的全部直接子任务改为“已完成”；
   - 只为截止日期为空的子任务补写父任务完成当天日期；
   - 已存在的子任务截止日期保持不变。
5. 完成日期按 `Asia/Shanghai` 的业务日期计算，不使用宿主机默认时区。
6. 父任务已完成后，不允许把其子任务改回“待办”或“进行中”；需要返工时先回退父任务。
7. 子任务截止日期可以在详情面板中修改或清空；清空通过显式 `clearDueDate=true` 表达，避免 Java DTO 无法区分“字段缺失”和“主动清空”。

## 界面方案

子任务区使用卡片化的紧凑列表：标题占据主要空间，右侧依次放截止日期、状态和删除操作；新建区域使用标题输入、可选日期和新增按钮组成的工具行，在窄屏下自动换行。状态和日期控件只有对应任务能力允许时可编辑，删除按钮只在 `canDelete` 为真时显示。

## 接口与事务

继续使用 `POST /projects/{projectId}/tasks`、`PUT /tasks/{id}` 和 `DELETE /tasks/{id}`，不新增接口。`TaskService.update` 负责校验已完成父任务的子任务不可回退，并在父任务完成时调用同一事务内的子任务级联方法。级联更新使用现有 MyBatis-Plus mapper 和审计服务，不走 Webhook 或前端补偿。

## 测试与验收

- 后端单元测试覆盖级联完成、缺失日期补齐、已有日期保留、已完成父任务下禁止子任务回退、主动清空截止日期。
- 前端测试覆盖状态选择、可选日期控件、能力控制和删除确认入口；全量测试、类型检查和生产构建必须通过。
- 已登录项目详情中，负责人可以修改自己有 `canEdit` 的子任务状态和截止日期，具备 `canDelete` 的用户可以删除子任务；普通只读用户不能操作这些控件。
