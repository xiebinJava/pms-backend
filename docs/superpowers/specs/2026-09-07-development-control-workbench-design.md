# 开发测试与项目控制工作台规格

## 背景

项目详情页的“开发测试与项目控制”节点需要承接需求确认和方案决策的结果，用一个可视化的树结构查看项目拆分出的专题、专题下的故事，以及开发测试进度。当前页面已有前端 Demo，但数据仍是静态种子，无法保存或协同使用。

## 目标

1. 在开发节点详情中真实读取并保存项目开发树。
2. 用“项目 → 专题 → 故事”的树结构承载开发拆分，不新增独立页面。
3. 项目进度、专题进度和统计数字全部由故事状态/进度汇总，避免手工维护汇总字段。
4. 保持轻量操作：默认以浏览和定位为主，编辑只围绕专题、故事和状态展开。

## 非目标

- 本次不建设缺陷管理、测试用例管理或完整研发任务系统。
- 本次不把开发故事自动复制为任务，也不改变现有任务看板的数据模型。
- 本次不做候选方案、版本分支或复杂迭代排期管理。

## 交互方案

### 浏览态

- 工作台展示项目汇总：专题数、故事数、已完成故事数、阻塞故事数、整体进度。
- 左侧树展示项目、专题和故事；专题默认可展开，点击专题后右侧展示专题摘要。
- 故事节点展示状态、进度、故事点和负责人；阻塞故事展示阻塞原因。
- 右侧显示专题负责人、迭代、构建版本、测试状态和阻塞信息。

### 编辑态

- 节点负责人或项目管理员可点击“新增专题”，创建专题并填写名称、专题负责人和迭代。
- 在专题编辑弹窗中创建故事并填写标题、故事负责人、故事点、状态、进度和阻塞原因；负责人只能选择项目成员。
- 点击“更新开发状态”打开当前专题的轻量编辑弹窗，一次保存故事状态、进度和阻塞原因。
- 没有编辑权限时，控件只读；后端继续做权限校验，不能只依赖前端禁用。
- 保存后重新读取工作台，项目汇总即时刷新。

## 数据模型

- `project_node_development_baseline`：一个项目开发节点一条基线，保存当前迭代和并发版本号。
- `project_node_development_topic`：专题，属于项目和开发节点。
- `project_node_development_story`：故事，属于专题，保存故事负责人、状态、进度、故事点和阻塞原因。
- 状态枚举：`NOT_STARTED`、`IN_PROGRESS`、`TESTING`、`DONE`、`BLOCKED`。
- 进度取值范围为 0–100；状态为 `DONE` 时前端默认建议 100，但后端不自动覆盖用户输入。
- 项目/专题汇总进度使用故事进度的四舍五入平均值；无故事时为 0。

## 接口

- `GET /api/projects/{projectId}/nodes/{nodeId}/development-control`
  - 返回基线、专题树、故事明细和派生汇总。
- `PUT /api/projects/{projectId}/nodes/{nodeId}/development-control`
  - 保存当前工作台完整树和基线版本。
  - 专题负责人和故事负责人必须是当前项目成员。
  - 仅允许项目管理员、项目负责人或节点负责人操作。
  - 使用版本号防止旧页面覆盖新数据；版本不一致返回冲突错误。

## 验收标准

1. 选中开发节点时，页面不再依赖前端静态 Demo 数据。
2. 新增专题/故事并刷新页面后，数据仍存在。
3. 更新故事状态或进度后，专题和项目汇总同步变化。
4. 非项目成员无法读写，非管理角色无法写入。
5. 空工作台有清晰空状态，并能从页面创建第一条专题。
6. 后端单元测试、前端测试、类型检查、构建和浏览器冒烟均通过。
