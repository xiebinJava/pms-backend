# 需求节点专属工作台设计

## 目标

将需求流程 Demo 中已经确认的节点详情和活动沉淀为正式的节点工作台组件。需求流程中除第一个“需求录入”节点外，每个节点都有对应的工作台候选，可以在流程模板中绑定；需求上线节点恢复“发布版本”必填字段；完成后移除 Demo 入口和 Demo 草稿能力。

## 现状问题

- Demo 只保存到浏览器 `localStorage`，没有写入流程模板定义。
- Demo 里的工作台活动与节点详情字段是两套独立数据，修改节点详情不会反映到工作台。
- 模板编辑器的组件库只有通用工作台，不能保证“需求接收工作台”不会被绑定到其他需求节点。
- 需求详情运行时只能识别既有组件，无法展示每个需求节点自己的工作台。
- 需求上线的正式节点定义中缺少“发布版本”。

## 方案

### 1. 节点专属组件

新增通用运行时组件 `requirement-node-workbench`。组件配置保存在节点自己的 `componentConfigs` 中，至少包含：

```json
{
  "nodeKey": "requirement-clarify",
  "nodeName": "需求澄清",
  "purpose": "补充背景、目标、边界和验收标准，形成可执行的需求说明。",
  "activities": [
    "补充需求背景与目标",
    "明确范围边界和约束",
    "确认验收标准",
    "记录澄清结论"
  ],
  "display": null
}
```

组件配置按节点保存，不使用跨节点共享配置。工作台标题、说明和活动由需求节点蓝图生成；节点详情字段仍以模板节点 `fields` 为唯一数据源，工作台不再复制一套字段编辑模型。

需求接收继续使用已有的 `requirement-receiving-analysis` 专用组件，因为它承载过滤、价值评分、接收/驳回等真实业务动作；它在组件库中只对“需求接收”节点出现。需求开发继续使用已有的 `requirement-execution` 目标绑定能力；其他需求节点使用新的节点专属工作台组件。

### 2. 模板编辑器绑定

- 选择需求管理流程时，左侧“业务工作台”只显示当前节点适用的工作台。
- 第一个“需求录入”节点不显示节点专属工作台候选。
- “需求接收”只显示需求接收分析组件；“需求开发”只显示需求交付目标组件；其余节点显示当前节点对应的 `requirement-node-workbench`。
- 点击添加后，将组件 key 写入当前节点 `contentOrder`，并将节点蓝图写入当前节点 `componentConfigs`。
- 已绑定组件继续显示在节点画布中；删除/排序只影响当前节点，不影响其他节点。
- Demo 入口、Demo 弹窗、本地草稿保存和相关文案全部移除。

### 3. 节点详情运行时

需求详情页收到 `requirement-node-workbench` 时，展示简洁的正式工作台：标题、节点目标、活动清单和必要的对象展示提示。字段填写继续由节点详情字段区负责，活动状态继续使用现有节点任务机制，不新增第二套活动状态存储。

### 4. 需求上线字段

需求管理流程中匹配“需求上线”的节点，若不存在 `release-version`，补充：

- 标签：`发布版本`
- 类型：单行文本
- 必填：是
- 绑定：无

上线检查、回滚方案、上线结论不恢复。

## 节点与工作台对齐

| 节点 | 节点详情重点 | 正式工作台 | 活动重点 |
| --- | --- | --- | --- |
| 需求接收 | 需求类型、战略契合度、接收结论 | 需求接收与分析 | 有效性判断、分类、价值评估、接收决策 |
| 需求澄清 | 背景、范围边界、验收标准、澄清结论 | 需求澄清工作台 | 补充背景、明确边界、确认标准、记录结论 |
| 需求整合 | 整合需求、需求规格、整合结论 | 需求整合工作台 | 查重、处理关系、统一描述、确认整合 |
| 需求排期 | 目标对象、计划时间 | 需求排期工作台 | 确认优先级、选择目标对象、安排窗口、确认依赖风险 |
| 需求开发 | 目标对象对应的项目/专题/故事结构 | 需求交付目标 | 绑定目标、确认落地范围、拆分执行事项、跟踪进度 |
| 需求验收 | 验收结果、业务确认、遗留问题、验收结论 | 需求验收工作台 | 对照标准、检查结果、确认业务结果、记录遗留问题 |
| 需求上线 | 发布版本 | 需求上线工作台 | 确认版本范围、上线前检查、交接与回滚、记录上线结果 |

## 兼容性与约束

- 保留既有 `requirement-receiving-analysis`、`requirement-execution` 组件及其已有配置。
- 后端模板校验允许新的 `requirement-node-workbench`，并限制它只能出现在需求管理流程。
- 老模板没有新组件时不自动批量绑定；只有在模板编辑器中添加后才写入 `contentOrder`。
- 未知组件配置继续按现有规则保留/拒绝，不影响其他节点。
- 不改变已发布模板版本的不可变语义；发布新版本时保存恢复后的“发布版本”字段。
