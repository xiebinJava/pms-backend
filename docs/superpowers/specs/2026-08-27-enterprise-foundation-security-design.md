# 企业级基础能力一期设计：登录安全、审计与 MySQL 生产化

## 目标

面向单企业本地部署场景，补齐上线前必须具备的登录安全、可追溯审计和 MySQL 生产检查能力。生产环境只使用 MySQL；测试环境可以使用隔离测试配置验证代码，不改变生产连接方式。

## 范围

1. 登录成功、失败、锁定、禁用和过期会话均写入 `sys_login_log`，不记录密码、JWT 或刷新令牌。
2. 连续登录失败达到配置阈值后账号锁定，失败计数和登录日志必须在认证异常返回后仍然持久化。
3. 生产默认不返回明文密码重置令牌；必须配置通知器或显式开启开发模式。
4. JWT 密钥不得使用空值或短密钥启动；CORS 不允许带凭据的通配来源。
5. MySQL 预检脚本校验连接、必需表、关键索引、邮箱唯一性及旧英文名兼容字段唯一性、组织引用和项目归属；预检只读且不输出密码。

## 非目标

- 本期不引入多租户字段。
- 本期不改动项目业务页面和组织架构交互。
- 本期不执行生产数据库删除、覆盖或自动回滚。

## 验收标准

- 错误密码返回 401，同时 `failed_login_count` 增加并产生 `FAILURE` 登录日志。
- 达到阈值后账号状态为 `LOCKED`，后续请求在锁定期内返回“账号已暂时锁定”。
- 成功登录清零失败计数并产生 `SUCCESS` 日志；禁用账号、锁定账号和不存在账号均使用统一错误文案，不暴露账号是否存在。
- 生产配置缺少 `PMS_JWT_SECRET` 或密钥少于 32 字节时启动失败。
- 生产配置的 CORS 只允许显式来源列表，默认不使用 `*`。
- `enterprise-preflight.sh` 和 `verify-enterprise-migration.sh` 的检查项覆盖上述生产要求。
