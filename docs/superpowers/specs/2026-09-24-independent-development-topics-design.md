# 专题与故事的可选关联设计

## 背景与目标

专题当前强制关联一个项目及其流程节点，故事也必须属于一个专题。产品规则现已明确：专题可以独立存在或关联项目；故事可以独立存在或关联专题。专题/故事负责人、流程节点负责人和任务执行人可从公司全员中选择；若专题/故事处于某项目下，相关人员不在该项目成员中时，保存操作自动将其加入为普通项目成员；解除关联后按自动加入来源和剩余引用安全回收。未关联项目的专题、独立故事及其流程对所有具有研发查看权限的用户可见。

本设计扩展现有专题、故事和研发事项流程模型以支持可空项目上下文，不创建平行的“独立专题”子系统，也不伪造隐藏项目或项目节点。

## 已确认规则

- 创建/编辑专题时，名称必填；负责人可选，候选人为公司内状态为 `ACTIVE` 且未删除的用户；项目关联可选。
- 故事的专题关联可选。故事关联专题时，其项目及项目节点上下文从专题派生，不提供独立的项目关联；故事未关联专题时，项目及项目节点上下文均为空。
- 专题/故事负责人、流程节点负责人和任务/子任务执行人均可从全公司状态为 `ACTIVE` 且未删除的人员中选择。只要专题/故事关联项目，其事项负责人、流程节点负责人和任务/子任务执行人就自动确保以普通成员身份加入该项目；已有成员角色保持不变。
- 自动加入规则适用于所有修改上述人员的入口，包括专题/故事编辑页、专题/故事流程详情和项目节点“开发与迭代控制”组件。未绑定项目的事项不产生项目成员关系。
- 解除专题与项目关联，或解除故事与专题关联时，释放因此失效的项目成员关联引用；只有系统自动加入、已无其他专题/故事/节点/任务引用、且仍为普通成员角色的用户才从项目成员中移除。解绑不移除原本就在项目中的成员，也不移除仍被同项目其他事项引用的成员。
- 人员从 owner/node/task assignment 中清除或替换时，也释放旧人员的对应关联引用；若该人员仍有其他有效引用则继续保留项目成员身份。
- 未关联项目的专题、独立故事及其流程，对所有具有研发查看权限的用户可见，不按项目成员范围过滤。修改/删除仍需研发编辑权限；已关联项目的事项继续遵守该项目的读取和写入权限。
- 无项目专题仍可绑定已发布的专题默认流程，展示其流程节点，并管理节点负责人、排期、模板字段、任务与子任务。
- 故事可独立存在，也可关联一个专题。关联专题后，故事继承专题的项目和配置节点；解除专题关联后，故事及其流程的项目/项目节点上下文清空，但保留故事本身及流程、任务历史。
- 绑定项目时项目必须处于进行中，并且包含专题流程模板配置的目标项目节点；目标节点仍由稳定 `nodeKey` 解析，前端不提交可伪造的节点 ID。
- 编辑时可把已有专题从项目改绑到另一个合格项目，也可解除项目关联。解绑不删除专题/故事/流程/任务数据。
- 每个专题/故事已实例化的流程继续固定其流程模板版本。模板版本变化不自动改变现有流程、项目关联或项目节点。

## 方案比较

1. **现有关联列允许为空，并使流程服务支持无项目上下文（采用）**：保留现有专题、故事和流程实例身份及外键，只将项目上下文改为可空；以事项及模板版本作为流程主关系。一次迁移覆盖数据库、服务端校验、查询和前端呈现，保持已关联数据原样。
2. **新增独立专题/故事/流程表**：隔离模型但复制现有列表、详情、任务、软删除和审计逻辑，后续两套模型容易分叉。
3. **表单允许不选项目，但先禁用流程和故事，直到绑定项目**：数据库影响较小，但专题创建后并非完整可用事项，不符合独立使用需求。

采用方案 1。项目及节点是可选的来源上下文，不是专题、故事或其流程实例的身份依据。

## 数据关系与生命周期

### 独立创建与运行

- 新专题写入 `project_node_development_topic` 时 `project_id`、`node_id` 均可为 `NULL`；仍初始化基本专题状态与创建审计信息。
- 专题流程实例在 `pms_development_item_workflow` 中仍由 `(item_type, item_id)` 唯一标识，并固定已发布默认模板版本；`project_id` 与 `source_node_id` 均可为空。
- 流程节点、节点字段值、任务和子任务仍关联流程实例及其节点，不依赖项目表。无项目专题仍可通过事项流程维护完整交付过程。
- 故事通过可空的 `topic_id` 关联专题；故事自身的 `project_id`、`node_id` 可空，并在关联专题时从专题派生、解除关联时清空。故事流程实例采用相同的可空项目上下文规则。
- 缺少专题默认已发布流程模板时，沿用专题创建的既有校验：拒绝创建并提示管理员先发布、设为默认；不创建无模板的半成品专题。

### 绑定、改绑与解绑

- 新建专题未选项目：保存空项目上下文并初始化专题流程；不要求之后补绑项目才能使用专题流程和任务。没有项目上下文时不记录人员的项目成员引用。
- 新建专题选项目：验证项目为进行中、操作者可管理项目、目标节点存在，再以该项目及节点初始化上下文；所选专题负责人及初始化流程中已有的节点/任务人员按普通成员规则自动加入目标项目并登记引用。
- 新建/编辑故事时不选专题：保存 `topic_id = NULL`、项目及项目节点上下文为空，并可独立维护故事流程和任务。
- 新建/编辑故事时选择专题：专题必须存在且未删除；故事继承专题的项目/节点上下文。若专题已绑定项目，所选故事负责人按普通成员规则加入项目；之后保存该故事流程节点负责人或任务执行人时，同样自动加入并登记引用。
- 将专题由无项目绑定到项目，或在项目间改绑：在单个事务中锁定专题、所属故事、专题/故事流程实例、流程任务、人员分配引用和涉及的项目成员；解析专题模板当前配置的稳定项目节点 key；更新专题、故事和对应流程实例的上下文；清空只对旧项目有效的 `milestone_id` / `iteration_plan_id`；将专题/故事负责人、流程节点负责人及任务/子任务执行人登记为目标项目的有效关联人员。任一校验或写入失败则整体回滚。
- 解除专题的项目关联：在单个事务中清空专题、其关联故事及其流程实例的项目/节点上下文，并清空里程碑/迭代计划引用；保留专题、故事、模板版本、流程节点状态、字段值、负责人、任务/子任务及审计历史；释放这些事项在原项目下的人员分配引用，并按回收规则清理确由系统自动加入且已无其他引用的普通成员。
- 将故事关联到另一专题或解除关联：在单个事务中同步故事的 `topic_id`、项目/项目节点上下文、流程实例上下文，并清空只对旧上下文有效的迭代计划引用；将该故事负责人、流程节点负责人及任务/子任务执行人从旧项目释放并向新项目登记。解绑不删除流程或任务历史；成员回收遵循自动来源及剩余引用规则。
- 上下文解绑不修改事项内部的流程节点 ID，因为那些是事项流程节点，不是项目节点。
- 对已经关联项目的记录，模板之后更改绑定节点不自动迁移现有记录；只有该专题被明确改绑时才按当时配置重新解析节点。

## 权限和人员选择

- 专题、故事和流程详情 API 仍要求已有研发模块权限。项目关联为空时，列表及详情以 `PROJECT_READ` 为访问边界，不要求成员加入任一项目；已关联事项仍使用既有项目读取权限。
- 无项目专题的维护、流程节点编辑、任务增删改和节点推进使用 `PROJECT_WRITE`。有项目事项还必须满足对应项目写权限。软删除/恢复遵循现有专题治理权限，并且未关联项目时不可调用项目 ACL。
- 负责人、专题/故事流程节点负责人及任务/子任务执行人接受全公司 `ACTIVE`、未删除账号；服务端必须独立验证用户存在且可用。任何绑定项目的专题/故事人员分配都会建立该用户对项目的分配引用，并在用户尚非项目成员时自动创建普通成员关系。
- 使用独立的项目成员自动管理标记和分配引用记录区分“系统为事项自动加入”与“原本/人工维护的成员”，并按专题 owner、故事 owner、流程节点 owner、任务 assignee 的稳定来源 ID 跟踪当前引用。既有成员不标记为自动加入；解绑/改派时删除旧引用；仍有引用时保留成员；引用归零时仅删除由系统自动加入且仍为普通成员的项目成员。人工修改自动加入成员的角色后，将该成员转为人工维护，后续不自动移除。
- 自动成员、自动管理标记、引用记录与事项/工作流/任务更新在同一事务提交；失败全部回滚。重复设置相同人员不重复生成成员关系或分配引用。
- 若已指派人员之后停用，历史负责人和任务执行人继续展示为历史值；不因读取详情而清空。停用人员不能作为新指派或变更后的目标人员。
- 所有人员选择器复用现有 `/users/search` 全员搜索和远程搜索交互；搜索结果只呈现可用账户，已保存的停用历史指派以只读历史标签展示。

## 列表与详情体验

- 专题列表混合展示当前用户可读的项目专题以及全部未关联项目专题；删除列表同样包含用户可治理的无项目专题。
- 项目筛选只筛选已关联该项目的专题，不关联任何项目的专题不会被隐式放入某个项目结果。
- 无项目专题的项目列展示“未关联项目”，不渲染项目或项目节点链接；有项目专题继续显示项目和模板配置的项目节点。
- 故事列表展示用户可读项目下的专题故事、无项目专题下的故事及未关联专题的独立故事；专题/项目上下文为空时显示“未关联”，项目筛选不命中这些记录。
- 专题详情页无项目时省略来源项目/项目节点链接，但保留专题流程摘要和节点详情；故事详情页仅在有关联专题时显示专题入口，项目上下文按可空值显示。
- 专题项目关联、故事专题关联均可在创建/编辑时选择或清空；负责人选择不依赖关联选择，改绑/解绑关联时不清空负责人。

## 兼容性与迁移

- 新增 Flyway 迁移将专题、故事及事项流程表的项目上下文列（流程表对应 `source_node_id`）设为可空，并将故事 `topic_id` 设为可空；新增项目成员自动管理标记/分配引用存储；保留原有外键、索引和所有已存关联值。历史迁移文件不回改，既有项目成员不推断为系统自动加入。
- Java DTO/实体和前端类型表达项目 ID、节点 ID 可空；详情、列表、审计和项目工作台对 `NULL` 上下文显式处理，不做对空值的解引用。
- 项目工作台派生专题组件仅针对实际绑定到项目节点的专题显示；无项目专题不占用、也不虚构项目节点。
- 现有已绑定专题/故事、正常列表、项目筛选、改绑及项目节点工作台行为保持不变。新增无项目路径不能扩大已绑定项目事项的数据读取范围。
- 删除/恢复专题沿用现有软删除规则；父专题删除时隐藏其故事但保留流程与任务，恢复时重新显示。

## 不在本次范围

- 创建新用户、改变账号状态规则或自动授予项目管理员/所有者角色。事项人员按本规则自动成为普通成员并在关联解除后安全回收，不视为超出范围。
- 修改项目本身的流程、节点、项目任务及其看板。
- 新增专题/故事的全局统一看板、通知策略或跨专题任务汇总。
- 更换已创建专题/故事绑定的流程模板版本，或因模板发布自动迁移既有专题的项目上下文。

## 验收标准

1. 不选择项目也可创建专题；负责人候选来自公司所有 `ACTIVE` 且未删除账户。绑定项目的专题/故事 owner、流程节点 owner 和任务/子任务 assignee 均确保加入普通项目成员；已有成员角色不被覆盖；无项目上下文时不创建成员关系。
2. 无项目专题仍绑定已发布专题默认模板；专题详情可读取流程、编辑所有未完成节点、维护字段和节点任务，刷新后数据保留。
3. 具有研发查看权限但不属于任何项目的用户，可以在专题列表、删除列表及详情查看无项目专题；不能据此读取其无权查看的项目专题。
4. 故事可以不关联专题独立创建，也可以关联或改绑到未删除专题；无专题故事的 `topic_id`、项目/节点上下文均为空，关联后从专题派生项目/节点；解绑或改绑后流程上下文同步且任务历史保留。
5. 从各业务入口修改专题/故事负责人、流程节点负责人或任务执行人时，服务端拒绝不存在、停用或删除的账户；绑定项目的相关人员均获得普通项目成员关系。
6. 绑定项目时，只允许进行中且含模板目标节点、且操作者有管理权限的项目；专题、其故事及流程实例上下文一致更新，所有人员分配建立项目引用，所有流程和任务历史保持不变。
7. 解绑项目或专题后，相应专题/故事/事项流程的项目/节点上下文为空，里程碑与迭代关联被清理，流程节点/字段/任务保留；原有成员和仍被其他事项引用的人员保留，系统自动加入且无剩余引用的普通成员被移除；页面显示未关联状态。
8. 现存非空项目及专题关联在迁移后完全保留；已有项目专题的读取、写入权限及项目节点组件派生行为不回归。
9. 并发绑定/解绑、无效项目/专题、缺少配置目标节点、重复分配及部分写入失败均不会留下专题/故事/流程/成员标记/引用不一致；成员引用归零时只回收符合自动管理条件的普通成员。
