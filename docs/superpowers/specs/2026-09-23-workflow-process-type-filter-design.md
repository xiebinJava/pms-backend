# 流程模板按流程类型筛选设计

日期：2026-09-23

状态：待用户评审

## 1. 目标

将流程模板配置页中的“项目类型”明确为可扩展的“流程类型”，用于筛选和维护不同业务流程模板：

- 项目管理
- 专题管理
- 故事管理
- 后续可由管理员继续新增其他流程类型

专题、故事等流程类型只用于流程模板配置和筛选，不出现在普通“新建项目”的项目类型选择中。

## 2. 当前问题

当前 `pms_project_type` 同时承担两个含义：

1. 流程模板的分组维度，后台模板页已经可以按 `projectTypeId` 加载模板。
2. 新建项目时的项目类型，项目创建接口会使用它绑定默认流程版本。

如果直接把“专题管理”和“故事管理”加入现有列表，它们也会出现在新建项目弹窗中，导致专题/故事流程被误用于普通项目。

## 3. 方案选择

### 3.1 方案 A：只修改前端文案

将“项目类型”改成“流程类型”，但不调整数据范围。

不采用。专题和故事仍会进入项目创建选项，无法解决业务边界问题。

### 3.2 方案 B：复用现有类型表，增加项目创建可用标识

继续复用 `pms_project_type`、`projectTypeId` 和现有模板接口，在类型表增加“是否可用于新建项目”的标识：

- 后台流程模板配置读取全部启用的流程类型。
- 新建项目选项只读取允许项目创建的类型。
- 现有 `general` 类型保留为项目创建默认类型，并展示为“项目管理”。
- 专题管理、故事管理作为流程类型创建，默认不允许用于新建项目。

采用此方案。它保持现有模板、项目和版本绑定关系不变，迁移成本低，并且未来新增流程类型不需要新增表或修改前端枚举。

### 3.3 方案 C：新建独立流程类型表并替换现有外键

新增 `pms_process_type`，将模板和项目分别迁移到新的外键。

暂不采用。当前需求只是增加流程类型筛选和隔离项目创建范围，独立拆表会扩大迁移、兼容和数据回填范围。

## 4. 数据模型与兼容策略

在 `pms_project_type` 增加：

```sql
project_creation_enabled TINYINT NOT NULL DEFAULT 1
```

语义：

- `1`：允许作为新建项目的项目类型。
- `0`：仅作为流程模板分类，不出现在新建项目选项中。

实体和 DTO 使用 `projectCreationEnabled`。管理员新增流程类型时默认写入 `false`，避免新建的专题、故事或其他流程分类自动进入项目创建入口。

兼容已有数据：

- 历史类型默认按 `1` 处理，避免已有项目创建能力被隐藏。
- `general` 保持稳定编码，继续作为未指定项目类型时的回退类型。
- 启动初始化逻辑确保 `general` 的展示名称更新为“项目管理”，并幂等创建 `topic-management`（专题管理）和 `story-management`（故事管理）两个流程类型。
- 不创建专题/故事的默认模板版本；管理员可在对应流程类型下新建、发布并设置默认模板。
- 已有项目的 `project_type_id`、流程版本和节点数据不改写。

## 5. 后端行为

### 5.1 管理端流程模板

现有接口继续保留：

- `GET /admin/workflow-config/project-types`：返回全部启用流程类型。
- `GET /admin/workflow-config/templates?projectTypeId=...`：按流程类型筛选模板。
- 模板创建、保存、发布、归档和设置默认版本继续使用现有 `projectTypeId` 绑定。

接口字段仍可保持 `projectTypeId`，避免一次性改动所有项目、模板和 AI 调用链；用户界面和说明统一使用“流程类型”。

### 5.2 新建项目选项

`GET /workflow-templates/options` 只返回 `projectCreationEnabled = 1` 的类型及这些类型下的已发布模板。

项目创建服务必须再次校验传入类型的 `projectCreationEnabled`，不能只依赖前端过滤。直接传入专题或故事类型时返回明确业务错误，不创建项目。

未传项目类型时仍回退到编码为 `general` 的项目管理类型，保持现有兼容行为。

## 6. 前端行为

流程模板配置页：

- 将“项目类型”标签改为“流程类型”。
- 将“新增类型”改为“新增流程类型”。
- 选择流程类型后，只展示该类型下的模板；现有选择模板、编辑、发布、设置默认版本流程保持不变。
- 空类型仍展示新增流程类型入口。
- 新增流程类型表单继续支持编码、名称、说明；编码用于稳定识别，名称用于展示。
- 页面说明改为“按流程类型维护流程模板”。

项目新建弹窗：

- 继续显示“项目类型”和“流程模板”，不改成流程类型。
- 只展示允许项目创建的类型，因此只会出现项目管理及未来明确允许项目创建的类型。

中英文文案、无数据、加载失败、权限和表单校验状态同步更新。

## 7. 测试与验收

后端：

- 类型字段迁移和启动初始化可重复执行，不重复创建类型。
- 管理端类型列表包含项目管理、专题管理、故事管理。
- 新建项目选项不包含专题管理和故事管理。
- 直接使用专题/故事类型调用创建项目时被拒绝。
- 未指定类型仍使用 `general` 的默认发布版本。
- 现有模板版本选择、默认版本和跨类型校验不回归。

前端：

- 流程模板页显示“流程类型”，切换项目管理/专题管理/故事管理时只加载对应模板。
- 新增流程类型后自动选中该类型并进入其模板配置上下文。
- 项目新建弹窗的类型列表不显示专题/故事。
- 现有模板编辑器、发布、设置默认和归档交互保持正常。

手工验收路径：

1. 打开“配置管理 → 流程模板”。
2. 依次切换项目管理、专题管理、故事管理，确认模板列表隔离。
3. 在专题管理下新建并发布一个模板，确认它不会出现在项目新建弹窗中。
4. 新建一个普通项目，确认仍默认使用项目管理流程。
5. 刷新页面和重启后端，确认三类流程类型不会重复出现。

## 8. 非目标

- 本次不新增专题管理和故事管理的业务列表或详情页能力。
- 本次不改变项目、专题、故事页面的数据模型。
- 本次不重命名数据库表、接口字段或已有外键。
- 本次不自动生成专题/故事的具体流程节点；流程模板由管理员配置。
