# 专题与故事独立流程详情设计

## 目标

专题和故事列表中的每条记录都能进入独立详情页。专题详情使用管理员在“流程模板”中配置的专题管理流程，故事详情使用故事管理流程。每条专题/故事拥有自己的流程节点状态及节点任务，不改变其所属项目原有流程。

## 已确认的产品行为

- 点击专题名称或“详情”进入专题详情；点击故事名称或“详情”进入故事详情。
- 详情中的流程类型分别固定为 `topic-management` 和 `story-management`。
- 节点顺序、名称和说明来自对应流程类型的已发布默认流程模板。
- 专题/故事详情展示流程进度，并在对应节点下管理任务与子任务。
- 项目、专题、故事及后续接入的流程详情使用一致的页面布局；节点、节点字段和任务区按绑定的模板定义动态展示。
- 所有未完成节点（未开始和进行中）均可预先编辑负责人、排期、模板字段及节点任务；已完成节点只读。
- 节点资料自动保存：负责人选择和排期选择后保存；模板字段在失焦或点击编辑区外时保存，不显示单独的“保存”按钮。
- 节点可提前配置不代表可提前推进：只有当前进行中的节点可完成，节点仍按顺序流转。
- 专题仍关联来源项目和来源研发节点；故事仍关联所属专题、项目和来源研发节点。详情页展示这些上下文链接。
- 操作权限继续使用所属项目当前的读取/编辑权限边界。

## 建议方案

为每条专题/故事建立独立的流程实例，实例固定引用首次绑定的已发布模板版本，并为该版本生成独立节点实例。专题/故事节点不能复用 `project_node`：该表表达项目自身流程，复用会把专题流程混入项目流程及其项目节点看板。

节点任务与子任务保存在专题/故事流程实例范围内，并归属一个流程节点；它们显示在专题/故事详情的该节点下，不自动加入来源项目的项目级任务看板。已有的项目研发节点任务与专题/故事流程任务仍各自归属自己的节点。

## 流程模板绑定和旧数据

- 新专题/故事创建时若对应流程类型已有默认已发布模板，则立即绑定该版本并建立实例；若尚无默认模板，仍允许创建研发事项，详情提示流程未配置，待管理员配置后首次打开详情时再绑定。
- 迁移前已存在的专题/故事在首次打开详情时幂等建立流程实例，绑定当时的默认已发布版本。
- 首次绑定后版本固定；管理员以后修改或更换默认模板，只影响新建专题/故事，不改写已有流程和节点状态。
- 若对应流程类型没有默认已发布模板，详情显示明确的未配置状态并引导管理员完成模板发布/设为默认；不伪造空节点或改用项目流程。
- 并发首次打开同一条记录不得创建重复实例或重复节点。

## 已确认的产品决策

- 专题/故事流程任务只在所属事项的节点看板管理，不同步进来源项目的项目级任务看板。
- 节点按流程顺序推进；完成节点前，必须完成该节点全部任务和子任务。
- 未开始节点可提前设置负责人、排期、模板字段及任务；任务可提前维护，但不改变流程节点状态。已完成节点不可编辑，只有当前进行中的节点可完成。
- 专题/故事实例固定绑定创建时或首次补绑定时的默认已发布模板版本。

## 详情页内容

- 页头显示专题/故事名称、状态、负责人、来源项目，以及返回列表入口；故事页另显示所属专题链接。
- 流程导航按模板顺序展示节点名称、当前节点和完成状态。
- 节点详情按模板动态展示节点说明、负责人、开始/截止日期、配置字段及该节点任务看板；所有未完成节点均显示可编辑控件，已完成节点显示只读值。
- 负责人和排期变更后自动保存；模板字段在离开字段编辑区或点击外部后自动保存，不提供独立保存按钮。
- 任务看板支持新增、编辑、完成/恢复、删除任务及子任务；每个任务只归属于一个流程节点。
- 总进度按完成节点数计算；节点完成前必须先完成该节点下所有未删除任务及子任务。流程顺序约束为前序节点完成后才能开始/完成后续节点。
- 专题自身进度由专题流程实例计算；不再用关联故事平均进度覆盖流程进度。故事的开发/测试状态、构建信息仍作为专题/故事的研发补充信息展示，不代替流程节点状态。

## 数据和接口边界

- 新增通用研发事项流程实例、节点实例、节点任务及子任务持久化模型，事项类型只允许专题和故事，并包含所属项目 ID、来源项目节点 ID、事项 ID 和模板版本 ID。
- 为并发安全和归属校验增加唯一约束/外键或等价服务端校验；任务读写每次都校验事项、流程实例、节点和来源项目的归属一致。
- 新增按事项类型和 ID 读取详情/流程，以及节点操作、任务操作接口；复用现有项目权限服务进行授权，不接受客户端任意指定项目或模板版本。
- 专题/故事列表查询的项目上下文、所属专题、负责人和研发状态继续从现有研发数据读取；列表进度/流程状态改为流程实例摘要，未实例化的旧数据通过服务端懒初始化绑定默认流程后返回。
- 日志和错误返回不泄露其他项目事项数据；访问无权事项时遵循当前项目权限的不可见/拒绝规则。

## 前端路由与复用

- 新增 `/development/topics/:id` 与 `/development/stories/:id` 路由和对应详情页。
- 列表名称、详情操作都指向本事项详情；项目名仍链接回项目详情，来源研发节点也可从详情上下文回到项目。
- 新增通用事项流程详情/节点任务组件，通过事项类型差异配置标题、字段和上下文，避免复制两套流程/任务交互。
- 继续使用 PMS 现有页面头、卡片、节点流程导航、任务看板和响应式规范；不在事项详情挂载依赖项目节点 ID 的专属项目工作台组件。

## 不在本次范围

- 新建专题/故事表单、独立专题/故事创建入口或现有研发工作台的创建流程改造。
- 改写所属项目的流程定义、节点、项目级任务或历史生命周期记录。
- 流程模板自定义审批引擎、并行分支、跨事项任务或全局统一任务中心。
- 允许编辑已绑定事项的模板版本或自动把模板更新传播到进行中的事项。

## 验收标准

1. 专题列表名称和详情操作打开对应专题详情，故事列表行为相同；返回列表后仍保留当前列表类型。
2. 专题只加载专题管理默认已发布模板，故事只加载故事管理默认已发布模板；两者的流程节点和状态互不串用，项目流程节点数量和状态不变。
3. 首次打开已有事项只创建一个流程实例及正确顺序的节点；并发或重复读取不会重复生成。
4. 未开始节点可保存负责人、排期、模板字段，并可新增/编辑/完成/删除该节点任务和子任务；这些操作不推进节点状态。已完成节点只读。
5. 只有当前进行中的节点可完成；新增/完成任务和子任务只影响选中事项和所属节点；无权项目的事项/任务不可读写。
6. 自动保存后的节点信息及所有节点状态、流程进度和任务归属在刷新或重新登录后持久保留；事项列表显示对应流程摘要。
7. 没有默认发布模板时展示可理解的配置提示，且详情不会静默退回项目流程。
8. 专题、故事、项目三个详情路由可直接刷新；桌面和窄屏布局可操作。
