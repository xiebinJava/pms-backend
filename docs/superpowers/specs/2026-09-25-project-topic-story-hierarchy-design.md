# 项目、专题与故事层级及统一 UI 体系设计方案

## 1. 目标

建立清晰的“项目 → 专题 → 故事”工作项层级，并保证项目、专题、故事详情页始终使用同一套 UI 设计体系。

最终效果是：

- 流程模板决定展示哪些节点、字段和业务组件。
- 详情页统一决定背景、颜色、尺寸、间距、卡片和交互规范。
- 配置不同流程模板时，页面内容可以变化，但页面整体 UI 不发生漂移。
- 专题节点可以承载故事拆分组件，故事不再与专题处于同一级别。

## 2. 已确认的业务理解

### 2.1 层级关系

```text
项目
└── 项目流程节点 C
    └── 开发与迭代控制组件
        └── 专题 A
            └── 专题流程节点 D
                └── 故事拆分组件
                    ├── 故事 1
                    │   └── 故事流程节点
                    │       └── 故事任务和子任务
                    └── 故事 2
                        └── 故事流程节点
                            └── 故事任务和子任务
```

专题和故事不是同级对象：

- 项目节点承载专题。
- 专题流程节点承载故事。
- 故事拥有自己的流程节点。
- 专题节点任务与故事节点任务相互独立。

### 2.2 两层节点

系统中需要明确区分两类节点：

1. **专题节点**：属于专题流程，例如“需求调研”“开发与迭代”“发布上线”。故事拆分组件挂在专题节点上。
2. **故事节点**：属于故事流程，例如“故事编写”“故事开发”“故事测试”。故事任务和子任务挂在故事节点上。

故事不能把自己的故事节点误当作专题节点，也不能把故事任务直接放入专题节点任务板。

## 3. 领域关系和生命周期

### 3.1 项目与专题

- 专题可以独立存在，也可以关联项目。
- 关联项目时只能选择有权限且处于进行中的项目。
- 已完成、已终止、已删除项目不能新建绑定或改绑专题。
- 专题关联项目后，挂载项目节点由专题流程模板配置的稳定 `nodeKey` 自动解析。
- 用户改绑项目时不重新选择节点。
- 专题从项目解绑时保留专题流程、节点字段、负责人、排期、任务和历史数据，只清除项目派生关系。

### 3.2 专题与故事

- 故事可以独立存在，也可以关联专题。
- 故事不能直接关联项目。
- 故事关联专题后，自动继承专题当前的项目上下文。
- 故事所属专题节点由故事流程模板配置自动决定，用户创建或改绑故事时不手工选择节点。
- 故事从专题解绑后，项目上下文和专题节点上下文都清空，但故事自己的流程、字段、任务和历史记录保留。
- 故事改绑到其他专题时，自动落到目标专题配置的故事挂载节点。

### 3.3 任务归属

- 专题任务只能属于专题流程的某个专题节点。
- 故事任务只能属于故事流程的某个故事节点。
- 父任务和子任务都属于同一个故事节点或专题节点。
- 不允许跨节点移动任务。
- 不允许把故事任务复制为专题任务。

## 4. 流程模板设计

### 4.1 项目流程模板

项目流程模板配置：

- 项目流程节点。
- 节点顺序。
- 节点说明和交付物。
- 节点字段。
- 节点组件。
- 项目节点负责人和排期编辑能力。

项目创建后绑定一个已发布的项目流程模板版本。项目详情始终读取该版本。

### 4.2 专题流程模板

专题流程模板除配置专题自身流程外，还配置：

```text
专题能力挂载到哪个项目流程节点
```

例如：

```text
专题流程模板 → 项目挂载节点：项目开发与测试
```

这里的“项目开发与测试”只是当前模板选择的节点示例，不是代码固定的节点名称。
运行时，系统按照专题流程模板配置的稳定 `sourceProjectNodeKey`，在对应的项目流程节点下挂载“专题管理/开发与迭代控制”运行时组件。
如果后续把挂载点改为“项目交付”或其他项目流程节点，新建专题以及对应项目详情展示就应自动跟随新配置；代码中不得写死“开发与迭代控制”、`develop` 或某个数据库节点 ID。

专题实例创建后，专题流程实例已有的 `templateVersionId` 作为项目挂载模板版本快照，并新增 `projectMountNodeKey` 保存当时的项目挂载节点 key；实际项目节点 ID 仍保存为专题的项目上下文节点。已有专题继续使用自己的快照，不能因为默认专题模板改了挂载点而自动移动到另一个项目节点。

### 4.3 故事流程模板

故事流程模板除配置故事自身流程外，还配置：

```text
故事拆分挂载到哪个专题流程节点
```

例如：

```text
故事流程模板 → 专题挂载节点：开发与迭代（当前示例）
```

这里的“开发与迭代”只是当前模板选择的专题节点示例，不是代码固定的节点名称。运行时，专题流程模板配置哪个节点，哪个节点下就自动增加“故事拆分”组件。

两个挂载关系都使用稳定 `nodeKey`，不能使用数据库自增 ID。

## 5. 模板版本固定规则

模板的默认版本只用于创建新事项，不能实时改写旧事项。

```text
新建事项
  ↓
选择已发布模板版本
  ↓
保存 templateVersionId
  ↓
详情页读取该版本
```

具体规则：

- 草稿不会影响任何已有事项。
- 修改默认模板不会影响已有项目、专题或故事。
- 发布新模板版本只影响之后创建的事项。
- 已有事项的节点、字段、组件和任务结构保持不变。
- 项目、专题、故事详情不允许通过当前默认模板覆盖历史版本。

### 5.1 故事挂载版本快照

为防止故事模板修改后已有专题的故事拆分组件发生位置漂移，专题创建时需要保存当时生效的故事挂载配置：

- `storyMountTemplateVersionId`：故事挂载模板版本。
- `storyMountNodeKey`：故事挂载的专题节点 key。

新专题使用新的默认故事模板版本；已有专题继续使用原来的故事挂载节点。

如果用户选择的故事模板版本与专题保存的 `storyMountNodeKey` 不一致，系统拒绝创建或改绑，并提示需要使用匹配的故事模板版本。

这样可以保证：

```text
旧专题不会因新模板发布而移动故事组件
新专题可以使用新的故事挂载节点
历史故事流程不会被重写
```

### 5.2 项目节点挂载快照

专题流程实例的 `templateVersionId` 记录专题模板版本，新增：

- `projectMountNodeKey`：该专题创建/改绑时，专题能力挂载到的项目流程节点 key。
- `sourceNodeId`：当时解析出的实际项目流程节点 ID，仅作为运行时上下文，不作为模板配置依据。

因此，模板配置负责“专题能力挂到哪个节点”，流程实例快照负责“这个专题当时挂在哪里”，项目详情页负责按照节点 key/节点 ID把专题组件渲染在正确位置。代码不得把某个节点名称、`develop` key 或数据库 ID 当成固定挂载点。

新建专题或改绑专题时，若绑定的项目流程版本中不存在配置的 `projectMountNodeKey`，操作必须失败并说明模板不兼容；不能自动回退到第一个节点或旧的固定节点。

## 6. 统一 UI 设计体系

### 6.1 基本原则

项目、专题、故事可以有不同业务内容，但必须共享同一套视觉基础。

模板只能决定内容，不能决定页面外观。

### 6.2 统一设计变量

建立统一的设计 token：

- 页面背景色。
- 卡片背景色。
- 节点区域背景色。
- 主要文本、次要文本和弱提示文本颜色。
- 边框颜色。
- 状态颜色。
- 圆角。
- 阴影。
- 页面内外边距。
- 标题和正文尺寸。
- 控件高度。
- 节点最小宽度。
- 任务看板列宽和间距。

以当前项目详情页的视觉规范为基准，专题和故事详情页统一复用，不再各自写一套颜色和尺寸。

### 6.3 统一基础组件

项目、专题、故事详情页统一复用：

- 详情页容器。
- 详情页头部。
- 流程节点导航。
- 节点详情卡片。
- 节点状态标签。
- 负责人选择器。
- 排期选择器。
- 动态字段渲染器。
- 节点任务看板。
- 空状态和错误状态。
- 运行时组件容器。

项目专属的项目成员、迭代计划、项目开发树等组件可以保留，但必须使用同一套设计变量和基础容器。

专题专属的故事拆分组件、故事专属的故事信息组件，也必须使用同一套基础容器。

### 6.4 运行时组件注册

运行时组件通过统一注册表管理：

```text
development-control → 开发与迭代控制
story-split         → 故事拆分
```

这里的 key 是“渲染什么组件”的注册 key，不是“挂载到哪个流程节点”的 node key；两者必须分离。

模板只能选择已注册组件。

未知组件：

- 保存或发布时拒绝。
- 详情页不渲染未知 HTML。
- 历史异常组件显示统一降级提示。

流程模板预览和真实详情页必须使用相同的节点、字段和组件渲染协议。

## 7. 页面展示规则

### 7.1 项目详情

```text
项目详情（挂载点由专题流程模板配置）
├── 项目基本信息
├── 项目流程
├── 当前项目节点
│   ├── 节点负责人
│   ├── 节点排期
│   ├── 节点字段
│   ├── 专题管理/开发与迭代控制（仅在配置的挂载节点显示）
│   │   └── 专题列表
│   └── 节点任务
└── 项目专属模块
```

项目侧可以展示专题数量、进度和故事数量摘要，但完整故事管理入口在专题详情中。项目流程节点名称、专题组件显示名称和实际挂载位置都来自模板配置或组件注册表，不能依赖固定文案判断。

项目详情应按专题实例的挂载快照和实际 `sourceNodeId` 将专题组件归入对应项目节点：如果旧专题仍挂在 C、新模板创建的新专题挂在 E，则 C、E 两个节点都可以各自展示属于自己的专题，不允许因为默认模板切换而把旧专题从 C 移到 E。

### 7.2 专题详情

```text
专题详情
├── 专题基本信息
├── 关联项目和挂载节点
├── 专题流程
├── 当前专题节点
│   ├── 节点负责人
│   ├── 节点排期
│   ├── 节点字段
│   ├── 故事拆分
│   │   ├── 故事列表
│   │   └── 创建故事
│   └── 专题节点任务
└── 专题信息
```

故事拆分组件只显示在模板配置的专题节点下。

### 7.3 故事详情

```text
故事详情
├── 故事基本信息
├── 所属专题和专题节点
├── 故事流程
├── 当前故事节点
│   ├── 节点负责人
│   ├── 节点排期
│   ├── 节点字段
│   └── 故事任务和子任务
└── 故事信息
```

故事详情中应显示：

- 所属专题。
- 所属专题节点。
- 继承的项目上下文。
- 故事自己的流程版本。

## 8. 权限和成员规则

- 独立专题和独立故事遵循研发模块权限。
- 已关联项目的专题和故事继续遵循项目读取/写入权限。
- 项目负责人、专题负责人、故事负责人、节点负责人、任务执行人和子任务执行人来自公司有效账号。
- 绑定项目后，相关人员自动加入项目普通成员。
- 解绑或改绑时，系统只回收自己自动加入且已经没有其他引用的普通成员。
- 人工维护的成员、管理员、项目负责人以及仍被其他事项引用的成员保留。
- 停用或删除的历史账号继续展示，但不能作为新的负责人或执行人。

## 9. 关键数据关系

故事需要同时保存两种关系：

```text
story.topic_id               → 所属专题
story.topic_workflow_node_id → 所属专题流程节点
story.project_node_id        → 继承的项目节点上下文
story.workflow_id             → 故事自己的流程实例
```

其中：

- `topic_workflow_node_id` 表示故事挂在哪个专题节点下。
- `project_node_id` 只表示项目上下文，不能代替专题节点。
- 故事自己的流程节点通过 `workflow_id` 关联。
- 专题改绑项目时，专题节点关系保持不变。
- 故事改绑专题时，系统自动重新解析目标专题的故事挂载节点。

## 10. 实施阶段概览

### 阶段一：统一 UI 设计系统

- 提取项目详情页设计 token。
- 统一项目、专题、故事的基础卡片和节点区域。
- 统一字段、负责人、排期和任务看板。
- 建立运行时组件注册表。
- 增加桌面端、窄屏、空状态和异常状态测试。

阶段 review：只检查 UI 和渲染协议，不改变业务关系。

### 阶段二：模板版本驱动

- 项目详情按项目绑定版本读取流程。
- 专题详情按专题绑定版本读取流程。
- 故事详情按故事绑定版本读取流程。
- 修复依赖全局默认模板的历史事项解析。
- 增加故事挂载版本快照。

阶段 review：修改默认模板后，历史项目、专题和故事的页面不能变化。

### 阶段三：专题节点承载故事

- 增加故事模板的专题节点配置。
- 增加专题节点合法性校验。
- 增加故事拆分运行时组件。
- 增加专题节点下的故事列表和创建入口。
- 保存 `topic_workflow_node_id`。

阶段 review：确认故事处于专题节点下，而不是与专题同级。

### 阶段四：关联和成员生命周期

- 完善专题绑定、改绑和解绑。
- 完善故事绑定、改绑和解绑。
- 同步项目上下文和专题节点关系。
- 补齐负责人、节点负责人、父任务和子任务成员引用。
- 增加权限和事务回滚测试。

阶段 review：确认上下文迁移不丢流程、字段、任务和历史指派。

### 阶段五：文档和最终验收

- 更新使用手册。
- 更新业务规则。
- 增加项目—专题—故事关系图。
- 增加流程模板配置说明。
- 完成后端、前端、类型、构建、Docker 集成和视觉验证。

## 11. 最终验收标准

### 业务关系

- 项目节点可以展示专题。
- 专题节点可以展示故事。
- 故事拥有独立流程节点。
- 专题任务和故事任务不会混淆。
- 故事不能直接绑定项目。

### 模板驱动

- 配置什么流程，详情页就展示什么流程。
- 节点名称、顺序和字段与绑定模板版本一致。
- 默认模板变化不影响历史事项。
- 草稿不会影响运行中的事项。

### UI 一致性

- 项目、专题、故事详情页使用统一页面背景。
- 卡片、节点、表单和任务看板尺寸统一。
- 颜色、字体、间距、圆角和阴影统一。
- 新增组件必须使用统一基础组件和设计 token。
- 模板不能破坏详情页整体布局。

### 故事拆分

- 故事拆分只显示在配置的专题节点下。
- 没有故事时显示统一空状态。
- 故事可以从专题节点进入故事详情。
- 独立故事不显示在专题拆分组件中。
- 故事任务只在故事详情的故事节点中管理。

## 12. 本轮不纳入范围

- 故事之间的复杂依赖关系。
- 故事拆分的多级父子树结构。
- 全局跨项目故事看板。
- 消息通知和提醒策略。
- 自动重写历史流程版本。
