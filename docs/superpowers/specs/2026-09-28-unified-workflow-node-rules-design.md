# 统一流程节点规则设计

## 目标

让项目、专题、故事（以及后续使用同一运行时的需求）在详情页拥有一致的流程节点交互和完成规则。流程模板只负责声明节点、字段和组件；运行时统一执行节点负责人、节点排期、模板必填字段、任务完成、完成和回滚规则。

## 已确认规则

1. 节点详情头部的主要操作放在最右侧；进行中节点显示“完成节点”。
2. 已完成节点可回滚。回滚目标节点恢复为进行中，后续节点恢复为未开始，之前节点保持已完成。
3. 完成节点前必须同时满足：节点负责人已设置、节点排期开始和结束日期完整且顺序正确、模板配置的可见必填字段已填写、当前节点任务和子任务全部完成。
4. 节点负责人和节点排期属于所有流程节点的固定必填规则，不依赖某一个模板名称或节点名称。
5. 新建或发布新的流程模板时，详情页仍然使用相同运行时规则；模板版本快照只决定节点内容，不改变统一规则。已经绑定流程实例的事项继续使用原快照；尚未创建流程实例的事项首次进入详情时才按当时的默认模板初始化。
6. 项目、专题、故事必须复用同一套状态迁移与错误提示语义；项目已有能力继续保留，并补齐缺失的排期校验。

## 技术方案

- 后端新增统一的节点完成策略校验器，负责固定元数据校验；模板字段校验继续使用现有 `WorkflowFieldValueValidator` 和项目自定义字段服务。
- 研发事项工作流服务新增回滚事务和控制器接口，使用工作流实例绑定的已发布模板版本，不重新解析当前默认模板；回滚事务锁定同一流程实例的节点集合，避免并发状态覆盖。
- 项目节点完成服务接入统一负责人/排期策略；项目已有回滚接口和权限体系沿用。
- 前端将研发事项节点操作对齐项目详情：完成按钮靠右，已完成节点显示回滚按钮，回滚要求填写原因，成功后刷新节点和当前选中节点。
- 所有行为通过后端服务测试、前端契约测试和浏览器交互冒烟验证。

## 非目标

- 不改变流程模板编辑器的节点定义格式。
- 不改变已发布模板版本的节点快照语义。
- 不在本次任务中增加新的流程组件。
