# PMS v0.1.0 发布记录（候选稿）

> 当前为发布候选记录，不代表 v0.1.0 已打 tag 或已通过生产验收。发布前必须完成下方阻塞项并由维护者确认。

## 发布边界

- 部署模型：单企业本地部署，不引入多租户。
- 运行时数据库：OceanBase MySQL 兼容模式，数据库 `brad_pms`；H2 仅用于测试和一次性历史迁移工具。
- 账号职责：`pms_app` 运行应用，`pms_migrator` 执行版本化 DDL/DML，`root@sys` 仅由 DBA 人工维护。
- 迁移版本：V1–V6，升级脚本具备幂等检查、命名锁和非空目标保护。

## 发布前阻塞项

1. 后端 CI 镜像依赖扫描仍发现高危/严重漏洞（Spring Boot/Spring Framework、Tomcat、MyBatis-Plus、Jackson、Logback、Connector/J 等），必须完成兼容性升级并重跑 Trivy；不能降低扫描阈值。
2. 后端集成 CI 需要仓库 secret `PMS_FRONT_REPO_READ_TOKEN`（仅 `xiebinJava/pms-front` Contents: Read），当前未配置。
3. 本机 Docker Hub 不可达，OceanBase 预检、逻辑备份、空库恢复和故障演练尚未完成；需在具备客户端/镜像缓存的部署机执行。
4. 目标环境前后端服务未运行，登录、权限、组织、导入、项目协作和桌面/390px 浏览器冒烟尚未完成。

## 发布步骤

1. 先完成 [`release-checklist.md`](../release-checklist.md) 全部条目并保存 CI、备份和验收证据。
2. 在两个仓库的发布提交上分别创建并推送同名 `v0.1.0` tag；tag 指向经 review 的 `main` 提交，不直接指向临时 feature 分支。
3. 发布说明必须同时链接后端和前端 tag、V1–V6 迁移说明、部署手册和回滚限制。

## 回滚限制

迁移脚本不提供 destructive rollback。验收失败时停止应用，恢复到新的空目标库并重新执行预检；禁止直接覆盖或删除现有 `brad_pms`。
