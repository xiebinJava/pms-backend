# PMS v1.0.0：企业级单企业私有化发布基线

发布日期：2026-08-31

## 发布范围

本版本是单企业、本地部署的企业级发布基线。运行时数据库只支持 OceanBase MySQL 兼容模式，数据库迁移历史为 V1–V10；H2 仅用于测试，不作为运行时数据库。

- 后端 `v1.0.0` 标签代码基线：`7cc2820`；标签之后的 `main` 仅追加文档收口提交。
- 前端 `main`：`1519e88736d2d9fe19c1e436b8a96cd66b1457bf`
- 版本标签：`v1.0.0`（后端、前端仓库均创建并推送）
- 迁移版本：V1–V10，包含邮箱归一化唯一索引、软删除/乐观锁、外键、任务附件、站内通知和通知节点标识

## 部署前必须由目标企业完成

以下项目依赖部署环境，不能由代码或发布标签代替：

1. 在后端仓库创建 `PMS_FRONT_REPO_READ_TOKEN`，只授予同 Owner 下 `pms-front` 的 Contents: Read 权限，并重跑跨仓库集成工作流。
2. 通过密钥管理器注入强 JWT 密钥、OceanBase 应用/迁移账号密码、SMTP 凭据和默认管理员初始化凭据；不得写入仓库、镜像或日志。
3. 由 HTTPS 反向代理终止 TLS，配置受限 CORS、可信代理头和 Actuator 访问网段。
4. 配置企业备份介质、RPO/RTO、恢复联系人、监控告警和慢查询阈值，并在目标环境重复迁移与恢复演练。
5. 若附件规模或并发超过当前单机阈值，再按 [`scaling-readiness.md`](../scaling-readiness.md) 迁移对象存储、分布式限流和集中式指标方案。

## 回滚与升级

- 发布前先设置 `PMS_OCEANBASE_VERIFY=true` 执行 `scripts/verify-oceanbase.sh`，再按 V1–V10 顺序升级；禁止跳过版本或手工修改迁移历史。
- 发生应用回滚时保留数据库迁移版本，不向后执行破坏性降级；优先回滚应用镜像并修复兼容问题。
- 数据恢复只允许写入明确的隔离空库，确认行数、关键约束和应用健康检查后再切换；不得覆盖现有 `brad_pms`。

本标签代表代码与本机演练通过的发布候选基线，不等同于任意企业生产环境已经完成配置认证。生产认证以目标企业的密钥、网络、备份和验收记录为准。
