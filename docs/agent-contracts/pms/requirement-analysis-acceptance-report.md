# 需求分析保存闭环验收报告

日期：2026-10-15（Asia/Shanghai）

## 结论

需求分析的确定性执行链路已经在一次性隔离 PMS 环境中通过：创建夹具、读取真实流程上下文、生成预览、执行保存、幂等重放、版本冲突拒绝和保存后回读均可验证；现有共享开发数据库没有被写入。

自然语言影子评估尚未运行。Connector 已提供 `AnalysisDraftProvider`、固定 Mock 和 OpenAI-compatible 外部模型实现，但本地没有配置外部模型凭据，也没有人工基线数据。因而本轮不把“聊天 UI 已验证”作为结论。下一步应先用影子用例完成模型质量和人工效率对照，再做最小的“草稿 → 预览 → 确认”入口；暂缓完整聊天工作台、自动推进和无人值守执行。

## 真实验收范围

- PMS Backend：一次性 MySQL 数据库、独立 API 端口和隔离管理员账号。
- Connector：`requirement-analysis` 场景及其 BrowserAuth、能力目录、context、preview/execute/readback 编排。
- 夹具通过注册的 PMS 操作创建需求，并通过注册的负责人、排期、字段更新和节点完成操作进入真实的“需求接收”节点；没有硬编码共享需求或节点 ID。
- 所有写操作均使用独立运行 ID、独立数据库名和新的幂等键；验收结束后销毁容器、网络和数据库卷。

## 发现并修复的边界

1. 能力目录此前只使用“允许新建项目”的流程类型，导致需求、专题和故事模板对 AI 不可见。能力目录现在读取所有活动流程类型，客户端可以从发布模板发现需求分析组件。
2. `AiContextReferenceProjector` 同时存在公开和内部构造函数，Spring 无法确定实例化方式。公开依赖构造函数现在显式标注注入，隔离服务可以正常启动。
3. 新建需求默认停在“需求录入”，且真实模板要求负责人、排期和业务线。夹具通过注册操作完成这些前置步骤，再使用当前节点版本进入需求接收；这保留了真实流程边界。
4. 版本冲突在当前自动执行接口表现为 HTTP 409 客户端冲突，而不是成功响应体中的 `CONFLICT` 枚举。Connector 影子入口需要把这个结果统一呈现为“未写入、请刷新后重新生成预览”，不能盲目重试。

## 自然语言影子用例

用例矩阵位于 Connector 的 [`requirement-analysis-shadow-cases.json`](../../../pms-ai-connector/tests/fixtures/requirement-analysis-shadow-cases.json)，共 12 条，覆盖：完整上下文、只读草稿、缺失背景、节点歧义、已有分析追加、无证据推断、未授权引用、旧版本、幂等重放、受保护字段、回读失败和非功能需求。

本轮只建立了可执行的评分矩阵，没有伪造模型输出或效率数字。每条用例需要记录：`AnalysisDraft` 的事实/推断/假设/待决策分类、来源覆盖、澄清问题数量、主动投入时间、总完成时间、修订次数和业务评审分数；同时保留 operationId、输入版本和最终读回结果。

## 产品决策门

| 门槛 | 当前状态 | 决策 |
| --- | --- | --- |
| 确定性保存链路通过 | 已通过 | 可继续做场景级验证 |
| 越权或受保护字段写入 | 本轮为零 | 保持窄写和拒绝策略 |
| 影子用例主动投入下降且质量不下降 | 尚未测量 | 不据此宣称效率收益 |
| 自然语言澄清和来源质量 | 尚未测量 | 先接入外部 AI 做影子运行 |

因此，本轮的产品结论是：上下文和保存契约达到进入自然语言影子实验的条件，但尚未达到建设完整聊天 UI 的条件。若影子实验达到预设质量和主动投入门槛，再实现一个复用同一场景 API 的预览优先入口；若失败集中在上下文缺失、节点选择或来源引用，先修契约和草稿校验。

## 清理与限制

隔离运行结束后已执行停止脚本，移除 API 进程、MySQL 容器、网络和数据库卷。真实 E2E 证明的是当前隔离种子数据和当前账号下的行为，不等同于所有生产模板、权限组合和模型输出都已验证。自然语言质量和人工效率仍待实际影子运行。
